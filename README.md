# GetPostsVK

Telegram-бот, который следит за постами публичных страниц VK и пересылает новые записи в чаты и темы форумов Telegram. Работает с `vk.ru` / `api.vk.ru`, рассчитан на запуск в контейнере на Debian 13 (trixie), веб-сервера у него нет.

## Быстрый старт

```bash
cp .env.example .env     # заполните BOT_TOKEN, VK_TOKEN, POSTGRES_PASSWORD
docker compose up -d --build
docker compose logs -f bot
```

Compose поднимает бота и Postgres 17. Если у вас своя база (Neon, Supabase и т. п.), удалите из `docker-compose.yml` сервис `db`, строку `DATABASE_URL` у бота и блок `depends_on`, а `DATABASE_URL` задайте в `.env`.

Бот в Telegram нужно сделать администратором чата, иначе он не увидит команды и не сможет писать в канал/тему.

## Команды (только для администраторов чата)

| Команда | Что делает |
|---|---|
| `/start` | приветствие и справка |
| `/push_domain` | подключить группу: бот попросит ссылку вида `https://vk.ru/имя_группы` |
| `/delete_domain` | показать подключённые группы и открепить выбранную |
| `/cancel` | отменить ввод ссылки |

Бот не работает с закрытыми группами. Подключение к теме форума определяется автоматически: команду нужно отправить в нужной теме.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен бота (обязательно) |
| `VK_TOKEN` | — | токен VK API (обязательно; старое имя `TOKEN` тоже работает) |
| `DATABASE_URL` | — | строка подключения к Postgres (обязательно; compose задаёт её сам) |
| `DB_SSL` | `off` | `off` / `require` (шифрование без проверки сертификата) / `verify` (с проверкой). Если не задано, берётся из `sslmode=` в URL |
| `PROXY_URL` | — | прокси для запросов к Telegram API, например `socks5://user:pass@host:1080` (также `socks4://`, `http://`). К VK бот ходит напрямую |
| `ADMIN_ID` | — | Telegram ID для уведомлений об аварии (старое имя `GOD_ID`) |
| `VK_API_VERSION` | `5.199` | версия VK API (старое имя `VERSION`) |
| `VK_API_HOST` | `api.vk.ru` | хост VK API |
| `POLL_INTERVAL` | `60` | секунд между проверками (не меньше 10) |
| `POSTS_PER_CHECK` | `10` | сколько последних записей стены смотреть (1–100) |
| `VK_REQUEST_DELAY` | `0.4` | пауза между запросами к VK, секунд |
| `LOG_LEVEL` | `INFO` | уровень логов |

## Переход со старой версии

* База совместима: таблицы и колонки те же, миграции не нужны. Если раньше соединение шло по SSL с проверкой сертификата, задайте `DB_SSL=verify` (или оставьте `?sslmode=require` в URL).
* Переименуйте переменные: `TOKEN` → `VK_TOKEN`, `VERSION` → `VK_API_VERSION`, `GOD_ID` → `ADMIN_ID` (старые имена пока читаются).
* Старые файлы с JSON-данными, `tests.py` и SQLite-файл не нужны.
* **Отзовите VK-токен из старого `bot/tests.py`** и выпустите новый: он лежал в публичном репозитории.

## Что изменилось

* `vk.com` → `vk.ru`: запросы идут на `api.vk.ru`, ссылки на видео и подсказки в боте используют `vk.ru`. Ссылки `vk.com` на вводе по-прежнему принимаются.
* Убран веб-сервер. Состояние «жив» определяется по heartbeat-файлу (`HEALTHCHECK` в образе).
* Корректно обрабатываются несколько новых постов за один проход (раньше терялись все, кроме последнего). Только что подключённая группа присылает один последний пост, как и раньше.
* Репост показывается вместе с комментарием репостнувшего. Фото берутся в большем размере. Длинные тексты режутся на сообщения, подпись к альбому ставится один раз.
* Один сбойный чат или недоступная группа больше не останавливают рассылку остальным. Чаты, из которых бота выгнали, отключаются автоматически, а переезд группы в супергруппу обрабатывается.
* Кнопка открепления проверяет, что нажал администратор. Раньше проверялись только сообщения.
* Уведомление администратору приходит один раз при аварии и один раз при восстановлении, а не каждую минуту.

## Разработка

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -t . -v
```

Структура: `app/posts.py` (разбор постов, без зависимостей), `app/vk.py` (клиент VK), `app/sender.py` (отправка в Telegram), `app/poller.py` (фоновая проверка), `app/handlers.py` (команды), `app/db/` (модели и запросы).
